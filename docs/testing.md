# Тестирование и отказоустойчивость

## 1. Стратегия

Тесты написаны на стандартном `unittest`, property-тесты - на `hypothesis`. Запуск не требует `pytest` и работает на чистом Python 3.11+ с установленной `hypothesis` для части тестов. Всего 106 тестов:

| Категория | Тестов |
| --- | ---: |
| модульные | 64 |
| интеграционные | 33 |
| property-тесты | 9 |
| **всего** | **106** |

Интеграционные тесты создают настоящий Git-репозиторий во временном каталоге, индексируют его, строят отчёты и вызывают CLI. Внешние демонстрационные репозитории для тестов не нужны, поэтому набор работает офлайн и быстро.

## 3. Property-тесты

`tests/test_properties.py` использует `hypothesis` с настройками `max_examples=60` и `deadline=None`. Проверяются свойства, а не конкретные примеры:

1. Коэффициент Пирсона всегда лежит в диапазоне [-1, 1].
2. Коэффициент Спирмена всегда лежит в диапазоне [-1, 1].
3. `rankdata` возвращает корректное ранжирование: длины совпадают, значения положительны, сумма соответствует средним рангам.
4. Z-оценки конечны, в том числе при нулевом стандартном отклонении.
5. Перестановочный p-value всегда в диапазоне [0, 1] и воспроизводим при одном seed.
6. `clamp` не выходит за границы и корректно обрабатывает перевёрнутые границы.
7. Процентиль лежит между минимумом и максимумом выборки.
8. Bus factor не превышает число авторов и не отрицателен.
9. `safe_div` возвращает значение по умолчанию при нулевом или близком к нулю знаменателе.

Property-тесты дополняют примеры, а не заменяют их. Например, точные значения Пирсона и Спирмена проверяются в `test_stats.py`, а границы - на случайных данных.

## 4. Что именно проверяет интеграция

Тестовый репозиторий `tests/helpers.py` содержит:

- 4 коммита и 3 авторов;
- несколько Python-файлов, включая пакет и модуль с импортами;
- тег `v1.0` и ветку `legacy`;
- коммит с сообщением о багфиксе;
- функцию с ненулевой сложностью.

На нём проверяется:

- полный импорт создаёт 4 коммита, 7 файлов, метрики, ряды, здоровье и минимум 3 среза;
- срез HEAD содержит узлы, срез тега имеет `ref = tag:v1.0`, срез ветки - `ref = branch:legacy`;
- инкремент после нового коммита добавляет ровно один коммит и разбирает только затронутые файлы;
- инкремент без изменений не создаёт новых срезов и не разбирает файлы;
- rebuild очищает прежние запуски и оставляет один новый;
- при расхождении истории инкремент автоматически превращается в полный импорт с предупреждением;
- HTML содержит разделы "Сводка", "Риски", "Динамика", "Граф", "Рекомендации" и не содержит `<script>`;
- PDF начинается с `%PDF` и имеет ненулевой размер;
- сравнение показывает здоровье 65.30 против 41.60 на демонстрационных данных и корректный вердикт;
- CLI возвращает код 0 и валидный JSON, а неизвестный репозиторий даёт понятную ошибку.

## 5. Запуск

```powershell
$env:PYTHONPATH = "src;."
python -m unittest discover -s tests -v
```

Ожидаемое время - около 37 секунд на локальном диске. Отдельный файл:

```powershell
python -m unittest tests.test_pipeline -v
```

Полный прогон вместе с демонстрацией, отчётами и замерами:

```powershell
python scripts\run_all.py --reindex --bench --tests
```

## 6. Отказоустойчивость

| Ситуация | Поведение | Проверка |
| --- | --- | --- |
| Каталог не является Git-репозиторием | `GitError` с понятным текстом | `test_git_runner.py` |
| Синтаксическая ошибка в файле | файл сохраняется с `parse_error`, импорт продолжается | `test_parser.py` |
| Битый плагин | плагин пропускается, остальные загружаются | `test_config_plugins.py` |
| Неизвестный ключ или битый `thresholds.json` | возврат к значениям по умолчанию | `test_config_plugins.py` |
| Расхождение истории | автоматический полный импорт с предупреждением | `test_pipeline.py` |
| Неизвестный режим импорта | `ValueError` до изменения данных | `test_pipeline.py` |
| Неизвестный формат отчёта | `ReportError` | `test_report.py` |
| Ошибка Git в одном срезе | срез пропускается, остальные создаются | `_create_snapshots` |
| Отмена импорта | `IndexCancelled`, запуск помечается отменённым | обработка в CLI и GUI |
| Нет reportlab | PDF возвращает понятную ошибку, HTML работает | `report/service.py` |
| Пустая история | пустые ряды и отчёт без деления на ноль | `safe_div`, `test_properties.py` |

Дополнительно:

- все SQL-запросы используют параметры, а не конкатенацию значений;
- схема создаётся идемпотентно, повторный запуск не ломает базу;
- соединения SQLite привязаны к потоку, включены WAL и foreign keys;
- фоновые задачи GUI ловят исключения и показывают их в журнале, не закрывая окно;
- внешние команды Git имеют таймауты 120 и 180 секунд;
- файлы больше 1.5 МБ и бинарные файлы пропускаются;
- размер среза ограничен 2500 файлами.

## 7. Детерминизм

- Все списки и SQL-выборки сортируются.
- Метрики времени считаются от максимального timestamp коммита, а не от текущего времени.
- Перестановочный тест использует seed 42.
- Тестовые репозитории создаются с фиксированными датами коммитов.
- Порядок плагинов и правил задаётся сортировкой по имени.
- Идентификаторы сущностей стабильны между запусками.

## 8. Соответствие требованию

Задание требует не менее 25 тестов и property-тесты или mutmut. В проекте 106 тестов, из них 9 property-тестов на hypothesis. Модульные тесты покрывают формулы и границы, интеграционные - сквозные сценарии на реальном Git, CLI и отчётах. Отдельного требования к проценту покрытия нет, поэтому метрика покрытия не заявляется.
