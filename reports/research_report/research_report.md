# Мини-исследование

## Гипотеза

Рост churn и снижение доли ведущего автора на неделе t связаны с ростом числа багфикс-коммитов на неделе t+1.

## Методика

Недельные ряды churn, доли ведущего автора и багфикс-коммитов строятся по истории Git. Для каждой недели t (кроме первой и последней) считаются: относительный рост churn g_t = (churn_t - churn_{t-1}) / max(churn_{t-1}, 1), падение доли лидера d_t = max(0, share_{t-1} - share_t) и число багфиксов на следующей неделе y_t = bugfix_{t+1}. Проверяются корреляции Пирсона и Спирмена, реализованные вручную, и перестановочный p-value для |rho| (500 перестановок, seed 42). Составной предиктор z(g_t) + z(d_t).

## Выводы

- Для здорового проекта связь составного предиктора с багфиксами оценивается как очень слабая (rho = 0.104, p = 0.018).
- Для проблемного проекта связь оценивается как очень слабая (rho = 0.104, p = 0.002).
- Гипотеза подтверждается частично: значимость зависит от длины истории, плотности релизов и эвристики определения багфикс-коммитов по сообщению.

## Ограничения

- Багфикс определяется по регулярному выражению в теме коммита, поэтому часть исправлений может быть пропущена.
- Недельная агрегация сглаживает короткие всплески и может размывать причинно-следственные связи.
- Корреляция не доказывает причинность; возможны общие факторы (релизы, миграции зависимостей).
- Метрики владения считаются по числу изменённых строк, а не по экспертизе автора.
- Перестановочный тест даёт грубую оценку значимости при малом числе недель.

## Воспроизводимость

Исследование выполняется командой `python -m projectpulse research --healthy <path> --problematic <path>` на зафиксированных коммитах из `repos.json`. Все пороги и seed детерминированы.
